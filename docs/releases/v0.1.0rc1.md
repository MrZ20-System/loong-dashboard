# LoongBoard v0.1.0rc1

> Release candidate · 2026-09-14

这是 LoongBoard 首个可发布候选版本，面向本地优先、单用户的工程工作台部署。代码、运行数据、Personal Data 和凭证保持分离；本说明只描述版本行为，不包含任何真实 token、password、主机地址或其他敏感值。

## 发布范围

- GitHub PR/Issue 活动列表、Merged 时间线、日期/状态/Domain 筛选，以及本地 Git diff、文件和目录阅读。
- 通过 Settings → Repositories 输入 GitHub URL、SSH 地址或 `owner/repo` 接入仓库。接入流程持久化验证、clone/复用、注册、初始化、首次同步和完成状态，并可在失败后恢复或重试。
- 示例配置默认提供 `vllm-project/vllm` 与 `vllm-project/vllm-ascend`。新接入仓库默认 10 个 Worktree slots，首次 GitHub metadata sync 默认回看 7 天；接入会同步初始化 Domain、Scheduler 和相关本地状态。
- PR 与 Issue 的状态和 archive 筛选支持多选；PR/Merged/Issue 等 GitHub 技术术语按原文显示。界面提供中文/英文常驻组件切换，用户采集内容、仓库名称、标签和 prompt 正文保留原有语言。
- Repository metadata retention 支持按 merged PR、closed PR、closed Issue 选择归档范围，payload prune 与 metadata archive 分开，restore/reopen 可解除归档。
- Personal Data V1：`knowledge/`、`prompts/`、`skills/` 三目录 Git 根、单分支导入、Instruction Tree 刷新，以及独立 checkpoint/push policy。
- 统一五字段 Cron 调度；Domain JSON 与 update prompt 支持版本化编辑，Agent update prompt 提供 Edit、Save、Restore 和明确的 JSON 输出格式约束。
- 外部 DSH runtime、持久 Agent session、Scheduler run history、本地可选 password lock，以及 Native/Docker 生产静态服务。

## 部署与升级注意

1. 使用与本版本相同的 Git revision 和 lockfile 构建镜像。Docker 运行时只挂载宿主机 data root 到 `/data`，配置使用 `/data/system.yaml`；凭证、SQLite、Personal Data、Settings、Domain 文件、Agent session 和 archive 都应落在该持久数据边界内。
2. 镜像不会复制 SSH key、GitHub token、provider secret、`system.yaml`、Personal Data 或 worktrees。凭证应在 Settings 保存，或通过受控的运行时环境/挂载提供；不要写入 Dockerfile、镜像层、YAML、日志或 Git。
3. 当前 Compose 直接绑定宿主机 `4174:4174`，应用监听容器的 `0.0.0.0:4174`。正式部署必须由部署机防火墙、安全组或上游网络 ACL 只允许明确白名单来源；仅在本机访问时才用 override 改为 `127.0.0.1:4174:4174`。不要依赖 SSH 隧道作为常规入口；应用本身不提供 IP allowlist。
4. 生产网络入口仍建议启用 Settings → Security 的 password lock。网络白名单是基础设施控制，password lock 是应用访问门禁，两者不能互相替代。
5. 升级前停止 Server/container 并备份完整 data root；不要只备份 `knowledge/` 或在线复制正在写入的 SQLite。执行 `docker compose down` 不会删除 bind-mounted data directory，重建镜像默认也不会删除其中数据。
6. 如果需要真正的全新部署，必须先确认备份和删除范围，再停止旧服务并删除指定的旧 data root、容器和镜像。删除 data root 会不可逆地移除 SQLite、会话、Personal Data、Settings、Domain 文件、凭证和 archive；这不是普通升级步骤。

## 已验证项

- `pnpm check:full`：截至 2026-09-14 的本地候选版本检查通过（包括 workspace 单元测试、lint、类型检查、架构/DSH pin 检查、生产构建和 3 项回归测试；合计 636 项测试）。
- 关键 Web 行为：双语 shell、PR/Merged/Issue 术语、主题图标、Status/Archive 多选、PR detail 全屏布局、Retention 卡片、Cron 帮助、Domain color 输入和 prompt 编辑/保存/还原。
- 关键 Server/contracts/database 行为：持久 repository onboarding、10 slots/7-day defaults、重复 query filter、metadata retention、Personal Data 路径边界、Cron canonicalization 和凭证不回显。
- 静态安全边界：`.dockerignore`/Dockerfile 不纳入运行凭证和用户数据；持久数据与镜像代码分离；镜像 checkout 无 `.git` 时 Code backup 明确标记不可用。
- 生产静态入口、health、auth、Repository、PR、Issue、Merged 和 Settings API 曾在临时 data root 的 native production smoke 中验证；服务关闭后监听端口与 HTTP probe 已确认停止。

## 已知限制

- LoongBoard 仍是单用户、单进程本地优先应用，没有产品级多用户权限、IP allowlist、分布式队列或跨实例锁。白名单必须由部署机或网络边界实施。
- Docker 镜像构建、重建、远程网络白名单和持久化行为需要在具备 Docker 与目标网络环境的部署机上复验；本机历史验收没有将其冒充为已验证。
- 没有有效 GitHub 凭证时，真实 GitHub 分页/同步无法完成；没有可用 DSH provider secret 时，不声明真实模型推理或工具调用已验证。
- Docker 镜像内应用 checkout 通常没有 `.git`，因此 Code backup 的自动/手工 checkpoint/push 会被禁用；Personal Data 或 Agent Archive checkpoint/push 仍要求目标目录是已存在且可写的 Git 仓库，系统不会自动 `git init`。
- Worktree 是可重建缓存，但 dirty、busy 或无法确认状态的 worktree 不会被自动清理；部署前应确认没有需要保留的未提交工作。
